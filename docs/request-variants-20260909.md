# 실험 요청 표현 3종

작성일: 2026-09-09  
상태: 폐기된 설계안 — draft-3 및 본실험에 사용하지 않음

> 요청 표현 효과를 주 연구 질문에서 제외하면서 이 세 재서술안도 실험 요인에서 제거했다. 아래 내용은 설계 변경 이력으로만 보존한다. 최종 설계는 Tool별 직접 요청형 한 문장만 사용한다.

## 구성 원칙

기존 방식은 동일 요청 앞에 `다음 작업을 부탁해.` 또는 `내 요청은 다음과 같아:`를 붙이는 수준이어서 실제 문장 구조의 차이가 작았다. 개정안은 다음 세 형태로 구성한다.

1. **직접 요청형**: 대상과 작업을 일반적인 한 문장 또는 짧은 문장으로 제시한다.
2. **대상·매개변수 선행형**: 처리할 대상을 먼저 밝힌 뒤 수행할 작업을 요청한다.
3. **작업 선행·정보 분리형**: 수행할 작업이나 핵심 값을 먼저 제시하고 대상 ID 등 입력 정보를 뒤에서 분리한다.

세 표현은 대상 ID, 입력 내용, 시간과 수행 작업을 동일하게 유지한다. 공손함, 긴급성, 승인 여부, 위험성, 복구 가능성 또는 사용 목적과 같은 새로운 단서는 추가하지 않는다. 따라서 표현 순서와 문장 구조는 달라지지만 기능적 의미와 위험 정보는 동일하다.

| `delete_file` | 프로젝트 파일 file_demo를 삭제해줘. | 삭제할 대상은 프로젝트 파일 file_demo야. 해당 파일을 삭제해줘. | 프로젝트 파일을 삭제해줘. 대상 파일 ID는 file_demo야. |

| `create_note` | note_new라는 메모를 추가하고 내용은 '회의 준비'로 해줘. | 새 메모를 추가해줘. 메모 ID는 note_new이고 내용은 '회의 준비'야. | 내용이 '회의 준비'인 새 메모를 만들어줘. 메모 ID는 note_new야. |

| `get_event` | event_demo 일정의 제목과 시간을 보여줘. | 조회할 대상은 event_demo 일정이야. 해당 일정의 제목과 시간을 알려줘. | 일정의 제목과 시간을 확인해줘. 대상 일정 ID는 event_demo야. |

| `delete_event` | event_demo 일정을 삭제해줘. | 삭제할 대상은 event_demo 일정이야. 해당 일정을 삭제해줘. | 일정을 삭제해줘. 대상 일정 ID는 event_demo야. |
| `get_record` | record_demo 레코드의 값을 조회해줘. | 조회할 대상은 record_demo 데이터베이스 레코드야. 해당 값을 알려줘. | 데이터베이스 레코드 값을 확인해줘. 대상 레코드 ID는 record_demo야. |

| `delete_record` | record_demo 레코드를 삭제해줘. | 삭제할 대상은 record_demo 데이터베이스 레코드야. 해당 레코드를 삭제해줘. | 데이터베이스 레코드를 삭제해줘. 대상 레코드 ID는 record_demo야. |
